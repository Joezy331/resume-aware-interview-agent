# 能力模型框架 ｜ Competency Framework

> 对应代码：`config.SCORE_DIMENSIONS` + `agents/score.py`
> 作用：定义面试评估的能力维度、评分锚点与证据要求，是「问题生成 → 评分 → 报告」闭环的度量基准。

---

## 1. 设计理念

能力模型回答三个问题：

1. **评什么**（维度定义）
2. **怎么评**（证据要求）
3. **评多准**（评分锚点）

模型采用 **6 维度、1–10 分、evidence-based** 设计，强调"每个分数都有依据"，避免 LLM 给出无支撑的主观印象分。

---

## 2. 六维能力定义

| 维度 | 定义 | 关键考察信号 |
|------|------|--------------|
| **沟通能力** | 语言表达是否清晰、逻辑是否连贯、能否准确传达观点 | 用词准确、结构分明、结论先行 |
| **技术深度** | 对技术栈的理解程度、是否具备岗位所需硬技能 | 能讲清原理、权衡与落地细节 |
| **项目经验** | 项目描述是否有细节、是否体现个人贡献与成果 | 量化成果、个人角色、踩坑与复盘 |
| **问题解决** | 面对追问的应变能力、思路是否清晰 | 拆解方法、边界判断、迭代思路 |
| **文化匹配** | 价值观是否与目标岗位匹配、团队协作意识 | 协作案例、冲突处理、价值观表达 |
| **成长潜力** | 学习能力、自我驱动力、职业规划清晰度 | 学习方法、自驱项目、阶段目标 |

---

## 3. 评分锚点（1–10）

| 分数 | 含义 | 典型表现 |
|------|------|----------|
| 1–3 | 明显薄弱 | 表达混乱 / 无细节 / 与岗位脱节 |
| 4–6 | 基本合格 | 能作答但缺乏深度或证据 |
| 7–8 | 良好 | 结构清晰、有具体案例支撑 |
| 9–10 | 突出 | 有量化成果、体现思考深度与自驱 |

> 每个维度评分必须返回 `evidence` 字段说明依据，未提供证据的分数视为不可信。

---

## 4. 与面试问题的映射

Interview Agent 生成问题时即标注 `dimension`，保证"问什么、评什么"：

- 引用简历具体项目 → 主要映射 **项目经验 / 技术深度**
- 从简到难梯度 → 后期问题更多映射 **问题解决 / 成长潜力**
- 动态追问 → 强化对薄弱维度的证据采集

---

## 5. 规划：岗位差异化权重

当前 6 维度等权由单一 Score Agent 评估。后续演进方向：

- **技术岗**：技术深度 / 项目经验 权重提升
- **产品岗**：沟通能力 / 问题解决 / 文化匹配 权重提升
- **数据岗**：技术深度 / 问题解决 权重提升
- **多面试官角色**：HR / Business / Professional / Leader 各自独立评分，由 Chief Evaluation Agent 汇总并检测评分冲突（>15 分差异进入仲裁）

> 差异化权重模板将作为独立配置，与 `SCORE_DIMENSIONS` 解耦，支持快速扩展新岗位类型。
