项目简介

五个维度 · 需求 / 机制 / 稳定性 / AI 接入 / 验证

需求洞察与产品定位

识别求职训练「上下文断裂、评估无标准」痛点，将产品从单次模拟工具重定位为简历全局上下文的持续训练系统，全链路贯通解析 · JD · 面试 · 诊断。

任务流与机制设定

构建「解析 → JD 双模式分析 → 多面试官模拟 → 多维诊断」Pipeline，设计 5 面试官矩阵、六维自适应评分权重（25/25/20/15/10/5，技术岗动态调权）与 12 行业 51 岗位能力标签库，收敛开放式生成为可控任务流。

稳定性与性能优化

结构化 JSON 范式 + 归一化容错层抑制生成波动，多模型降级池自动换模重试叠加本地规则兜底，模型下线 / 限流场景下功能降级而非中断。

AI 能力接入

OpenAI 兼容协议模型池动态同步（发现 → 排序 → 持久化 → 离线恢复，零硬编码清单），OCR 双链路竞速解析简历 / JD 截图，主进程代理实现 CORS 规避与密钥服务端隔离。

项目成果与数据验证

Electron 便携版零依赖交付；产出系统性量化评测报告（32 简历 × 56 场景 × 5 面试官 × 40 次压测），指标按可信度分级标注、支持一键复现，形成数据闭环。

数据可信度声明

主动亮出局限，比堆漂亮数字更可信
关于测试输入与方法边界（请在引用任何指标前先读这段）：
  • 评测输入为 32 份跨行业合成简历 / 56 个追问场景 / 32 个报告场景，明确为构造输入，不代表真实用户效果。
  • 离线匹配引擎为确定性可复现；真实模型接口调用存在温度方差（决策合理率 66%–71%），报告已标注。
  • 「追问相关性 2.68/5」「评分-证据一致性 92%」为启发式代理指标，保守下界，非人工标注黄金集。
  • P95 延迟偏高（追问 169.9s / 稳定性 23.3s）源于免费本地模型服务，已在产品中通过异步进度提示缓解。
  • 所有指标由实际运行计算，未为获得漂亮数据修改评分逻辑或硬编码答案，全程未输出任何 API Key。
  • 结论建议：生产环境应以「评分 + 人工复核」双轨呈现，不对候选人做单点自动化否决。
