03

方差、局限与未通过项

这一节是整份报告最有价值的部分
主动披露（面试官最先问的就是这些）：
  • 合成输入 ≠ 真实用户效果。32 份简历、56 个场景、32 个报告场景均为构造测试集，覆盖 11 个职业族与硬资格边界用例，不代表线上真实用户表现。
  • 非确定性方差真实存在。追问决策合理率在温度 0.2 下两次全量跑为 66%–71%，报告采用 71.4% 并同时标注区间，未挑选更好看的一次。
  • 代理指标不是黄金集。追问相关性 2.68/5、评分-证据一致性 92%、上下文利用 3.95/5 均为启发式计算（bigram + 数字引用 / 情感词典对照），是保守下界而非人工标注结论。
  • 存在明确未通过项。回归套件 6/7，唯一失败为 round4_check 的 pasteHasHard（粘贴 JD 未抽出硬技能），属真实产品缺陷，未修复、未掩盖；后续已在新版解析逻辑中处理。
  • 延迟偏高。追问 P95 169.9s（最大 180.9s）源于免费本地模型服务偶发限流；稳定性压测 P95 23.3s。产品侧以异步流式 + 阶段进度提示缓解。
  • 产品结论克制。因此建议生产环境采用「评分 + 人工复核」双轨呈现，不对候选人做单点自动化否决——这是评测结论，不是免责声明。

如果只能记住一句话

强候选人画像（CAND_STRONG）被 5 位面试官打出 23 分差距，真实触发了应用的 >15 分冲突检测——这证明多角色分歧检测不是写在 PRD 里的功能，而是在真实模型输出下会生效的机制；同时也说明「AI 评分不可单点采信」是这套系统从评测阶段就内置的假设。

05

一键复现

clone 仓库后，6 条命令重跑全部指标
# 前置：Electron 应用依赖已安装；本地 OpenAI 兼容接口在 localhost:8787
cd electron-app
node ../evaluation/run_match.js        # Test 1 离线确定性引擎（无需模型）
node ../evaluation/run_followup.js     # Test 2 真实接口 · 56 场景
node ../evaluation/run_report.js       # Test 3 真实接口 · 多角色评价
node ../evaluation/run_stability.js    # Test 4a 接口负载 40 次
node ../evaluation/run_regression.js   # Test 4b 产品回归套件
node ../evaluation/build_deliverables.js # 汇总生成 JSON / CSV / 报告
